# Мобильные кабинеты

В одном приложении доступны роли `manager`, `operator`, `worker`. Суперпользователь входит как руководитель. Роль приходит от сервера при входе и проверяется через `/api/mobile/me/` при восстановлении сессии. Установка APK и изменение роли не заменяют проверки прав на сервере.

- Мастер: существующие назначения, принятие, перенос, завершение с оплатой, история и личные показатели.
- Оператор: создание и редактирование лидов, город, услуга и время записи; создание заказа из лида; назначение мастера, возврат оператору и отмена с причиной; активные/закрытые заказы и поиск клиентов.
- Руководитель: функции оператора, выручка и расходы за сегодня, незакреплённые заказы, команда, просмотр ставок и включение/выключение приёма заявок.

Настройка ролей, создание сотрудников, изменение ставок и расчёты смен остаются в веб-интерфейсе. Мобильная сводка не заменяет расчёты смен.

Маршруты `/api/mobile/staff/` доступны только оператору/руководителю. Сводка, команда и изменение доступности — только руководителю. Маршруты действий мастера сохраняют проверку его роли и принадлежности заказа. Серверные сервисы назначений, Telegram-уведомлений и оплаты общие с веб-версией.

## Проверка и запуск

```powershell
.venv\Scripts\python.exe backend/manage.py check
.venv\Scripts\python.exe backend/manage.py test apps.accounts.test_mobile_staff apps.accounts.test_mobile_api --noinput
cd mobile
npm run typecheck
npm run export:android
npm start
```

Обновить backend и перезапустить приложение. При использовании установленного APK собрать и установить новую версию. Новых миграций для мобильных ролей нет. Идентификатор Android-пакета сохранён, отображаемое имя — CRM.
