# Неделя 2: PostgreSQL и SQL

## Сущности

| Сущность | Модель Django / таблица | Основные поля |
| --- | --- | --- |
| Employee (сотрудник) | accounts.User / accounts_user | id, username, first_name, last_name, email |
| Client | customers.Client / customers_client | id, name, phone, created_at |
| Service | services.Service / services_service | id, name, description, created_at |
| Lead | leads.Lead / leads_lead | id, title, client_id, service_id, employee_id, created_at |

Employee представлен уже существующей моделью User: отдельная таблица сотрудников сейчас дублировала бы учётные записи. Пароли создавайте через Django, а не обычным SQL INSERT.

Каждый id — primary key: уникальный идентификатор строки, генерируемый базой.
Поля client_id, service_id и employee_id — foreign key: ссылки на строки других таблиц.
У клиента, услуги и сотрудника может быть много лидов. Ответственный сотрудник необязателен.
В Django удаление клиента или услуги с лидами запрещено (PROTECT); удаление сотрудника обнуляет ответственного (SET_NULL).
Эти правила удаления реализует ORM Django. Прямой SQL DELETE не выполняет логику ORM: сначала самостоятельно обновите или удалите связанные записи.

Телефон хранится как текст, чтобы сохранить + и ведущие нули. Он не уникален: у клиентов может быть общий номер.
Название услуги уникально. Цена, статусы и автоматизация пока не добавлены.

## Индексы

PostgreSQL создаёт уникальные индексы для primary key и UNIQUE.
Django также создаёт индексы внешних ключей.
Дополнительно индексированы phone клиента (поиск по точному номеру) и created_at лида (фильтр по дате).
Индекс ускоряет подходящие запросы, но занимает место и добавляет работу при записи.
На маленькой таблице PostgreSQL может предпочесть последовательное чтение.

## Практика

Откройте docs/week-02.sql в SQL-редакторе PostgreSQL, подключённом к базе CRM, и выполните целиком.
Скрипт использует временную таблицу для идентификаторов учебных записей и заканчивается ROLLBACK: записи не сохраняются.
После отката номера id могут иметь пропуски — последовательности PostgreSQL не откатываются.

1. SELECT читает строки; WHERE фильтрует; ORDER BY сортирует.
2. INSERT добавляет строку; RETURNING возвращает её id.
3. UPDATE изменяет строки. Всегда проверяйте WHERE.
4. JOIN соединяет связанные строки. LEFT JOIN сохраняет лид без ответственного.
5. DELETE удаляет строки. Сначала удаляйте зависимые записи.
6. EXPLAIN показывает план выполнения, а не сами результаты.

Для запуска проекта из PowerShell в корне:
```powershell
.\.venv\Scripts\python.exe backend/manage.py migrate
.\.venv\Scripts\python.exe backend/manage.py runserver
```

В /admin/ доступны сотрудники, клиенты, услуги и лиды.
