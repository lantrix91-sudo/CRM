# Неделя 6 — Kanban: React + TypeScript + API

Откройте http://127.0.0.1:8000/kanban/ после входа через админку.
Из /leads/ доступна ссылка «Канбан». Используйте один адрес (localhost или 127.0.0.1) для входа и работы.

## Колонки
| Колонка | Lead.status |
| --- | --- |
| Новые | new |
| В работе | in_progress |
| Назначен | assigned |
| Выполнен | won |

Старый код won сохранён, изменена только подпись. Статус assigned добавлен миграцией.
lost не удаляется: такие лиды доступны по ссылке «Без сделки».
Этап «Назначен» сам по себе не назначает сотрудника. Заказ автоматически не создаётся.

Карточку можно перенести мышкой или выбрать статус в выпадающем списке — это работает с клавиатуры и на телефоне.
Порядок внутри колонки не сохраняется: лиды сортируются по дате создания.
Есть поиск по клиенту, телефону, услуге, обращению, источнику и сотруднику.

## Цепочка сохранения
1. Пользователь переносит карточку.
2. React сразу показывает новый статус (оптимистическое обновление).
3. fetch отправляет PATCH в Django с новым и предыдущим статусами.
4. Django проверяет сессию, права, CSRF и данные.
5. Один SQL UPDATE меняет строку только при совпадении предыдущего статуса.
6. React получает подтверждение и показывает сообщение о сохранении.

Пока запрос выполняется, другие переносы заблокированы.
При ошибке возвращается предыдущая карточка, затем приложение перечитывает доску:
сервер мог сохранить статус, даже если ответ потерялся.
Если повторное чтение не удалось, остаётся сообщение с предложением обновить доску.
Изменения других сотрудников автоматически не приходят — нажмите «Обновить».

## API
GET /api/leads/board/ возвращает leads, columns, archived_count, can_change, can_add.
PATCH /api/leads/123/status/ принимает:
~~~json
{"status": "assigned", "expected_status": "new"}
~~~
123 — пример; нужен настоящий id.
200 возвращает id и status. 400 — неверные или лишние поля, 403 — доступ/CSRF,
404 — лид не найден, 409 — другой сотрудник уже изменил статус.
expected_status защищает от перезаписи нового статуса устаревшей вкладкой; это не полная история версий.
API меняет только status, не клиента, название или ответственного.

Используется SessionAuthentication: браузер отправляет cookie входа в админку.
Для PATCH X-CSRFToken берётся из meta-тега, созданного Django. Секреты .env не попадают в React.

Нужны активный сотрудник, is_staff, leads.view_lead и customers.view_client.
Для переноса дополнительно нужно leads.change_lead. Без него доска доступна только для чтения.
Права проверяются сервером, а не только интерфейсом.
Доска общая для команды, а не только для лидов текущего сотрудника.

React-компонент — функция, возвращающая JSX (описание интерфейса).
useState хранит доску, поиск, ошибки и сохраняемый лид.
useEffect запускает загрузку при появлении компонента.
useRef хранит блокировку запросов без перерисовки.
TypeScript описывает Lead и допустимые Status и проверяет типы при сборке.
Но сервер всё равно проверяет входные данные через serializer.

## Проверки
~~~powershell
.\.venv\Scripts\python.exe backend/manage.py test apps.leads apps.orders --noinput
npm --prefix frontend run build
npm --prefix frontend test
~~~
Playwright использует установленный Microsoft Edge без видимого окна и временный Django-сервер на 8765.
Обычный npm test запускает 6 сценариев с имитацией API и пропускает сквозной тест без явного включения.

Для сквозного теста:
~~~powershell
$env:RUN_POSTGRES_E2E = "1"
try {
    npm --prefix frontend test
} finally {
    Remove-Item Env:RUN_POSTGRES_E2E
}
~~~
Он создаёт временные записи и сессию в настроенной PostgreSQL-базе, переносит карточку в браузере,
проверяет значение в базе и после перезагрузки, затем удаляет только собственные записи в finally.
Принудительное завершение процесса может помешать очистке.

При реализации прошли 26 Django-тестов на SQLite и 7 браузерных сценариев, включая PostgreSQL.
Для отдельной тестовой PostgreSQL-базы по-прежнему не хватает CREATEDB.
Сквозному тесту не нужно создавать базу, поэтому он работает с текущими правами.

Сейчас API загружает всю активную доску. Для большой базы следующий шаг — загрузка порциями по колонкам.
Автоматическое обновление других вкладок и сортировка карточек внутри колонки пока не реализованы.
