# Неделя 9 — лиды и настоящие заказы

Lead — потенциальная сделка/обращение, Client — сам клиент, Order — подтверждённая работа.
Один клиент может иметь несколько лидов и заказов.
Из одного лида создаётся не более одного заказа (OneToOneField).
Заказ можно создать и отдельно через админку: ссылка на лид необязательна.

## Рабочий путь
1. Откройте /admin/leads/lead/, отметьте нужный лид.
2. В действиях выберите «Клиент согласился: создать заказ».
3. Перейдите в /admin/orders/order/ (ссылка «Заказы» в Kanban).
4. Откройте заказ, назначьте активного сотрудника и укажите стоимость в KZT.
5. В списке заказов используйте действия «Начать работу», «Отметить выполненным».
6. После фактического получения денег — «Подтвердить получение оплаты».

Повторная конвертация возвращает существующий заказ. Лид получает статус converted («Создан заказ»).
Он остаётся в списке лидов, но больше не отображается на рабочей Kanban-доске.
Закрытый без сделки лид нельзя конвертировать.
Если у лида уже был активный сотрудник, он переносится в заказ; иначе заказ создаётся без мастера.
Клиент, услуга и название копируются при конвертации; дальнейшие изменения заказа не синхронизируют лид.
Удалить исходный лид при наличии заказа нельзя (PROTECT).

## Этапы Order
| Код | Значение |
| --- | --- |
| new | Новый, ожидает мастера |
| assigned | Назначен мастер |
| in_progress | В работе |
| completed | Выполнен, ожидает оплаты |
| paid | Оплачен |

Назначение мастера через форму переводит новый заказ в assigned; очистка мастера до начала работы возвращает new.
В работе менять мастера через форму нельзя. После выполнения мастер доступен только для чтения.
Переходы вперёд выполняются действиями админки и проверяются сервером.
Пропустить этап и отметить оплату до выполнения нельзя.
completed_at и paid_at заполняются автоматически, редактировать их в админке нельзя.
Для оплаты требуется положительная amount. После оплаты стоимость в форме заблокирована.

Оплата пока означает ручное подтверждение полного получения указанной суммы.
Платёжный провайдер, частичные платежи, возвраты и фискальные чеки не реализованы.
Стоимость хранится DecimalField, а не float. На этом этапе используется KZT.
Действия требуют orders.change_order. Конвертация требует leads.change_lead, orders.add_order и customers.view_client.
Отдельной роли кассира пока нет.

## Telegram
Очередь теперь может ссылаться либо на Lead, либо на Order — ровно на одну сущность, это проверяет база.
После конвертации старые уведомления лида отключаются.
Если мастер перенесён в заказ, ставится новое уведомление о заказе.
При назначении/смене мастера заказа в админке до начала работы также создаётся новое уведомление.
Принять → заказ in_progress. Завершить → completed с датой выполнения.
Отклонить до принятия → new без мастера. Диспетчер назначает другого через админку.
Оплату кнопки Telegram не подтверждают.
Старые лиды без конвертации временно сохраняют прежнюю логику Telegram; для новых работ используйте Order.

## Распределение и сохранение данных
Распределение недели 7 теперь учитывает суммарную загрузку: активные лиды и заказы new/assigned/in_progress.
Конвертированный лид не учитывается второй раз.
Автоматический подбор пока запускается для лидов. Мастера заказа выбирают вручную в админке.
Существующие заказы сохранены: с сотрудником получили assigned, остальные new.
Исторические заказы не рассылаются в Telegram автоматически при миграции.
Исторические связи Lead → Order не угадываются.

## Проверки
Прошли 54 теста на SQLite. На PostgreSQL с откатом проверены 8 сценариев заказов и полный путь через админку:
создание из лида → сохранение стоимости → работа → выполнение → оплата.
Telegram в этих проверках имитируется: реальные сообщения не отправлялись.
Миграции применены, сборка React обновлена.
