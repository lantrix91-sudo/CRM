# Неделя 8 — Telegram

## Что подключено
После назначения кнопкой «Подобрать сотрудника» CRM создаёт запись очереди в той же транзакции.
Отдельный процесс отправляет сотруднику личное сообщение:
~~~
🔔 Новый заказ
Ремонт стиральной машины
Клиент: Иван
Район: Центр
Телефон: +7…
Заявка № …
~~~
Здесь «заказ» в тексте — назначенный Lead из Kanban. Отдельная модель Order пока не изменяется.

Первое сообщение содержит «Принять» и «Отклонить».
После принятия кнопки заменяются на «Завершить»:
- Принять: assigned → in_progress.
- Отклонить: assigned → new, ответственный очищается.
- Завершить: in_progress → won.

После отказа диспетчер решает, кому назначить лид. Автоматического повторного назначения нет.
Подбор может снова выбрать того же сотрудника: история отказов пока не влияет на алгоритм.
Для обновления Kanban нажмите «Обновить».

## Настройка
1. Создайте отдельного бота через @BotFather и получите токен.
2. В локальный .env добавьте TELEGRAM_BOT_TOKEN=ваш_токен. Не коммитьте токен и не вставляйте его в исходный код.
3. Из корня проекта запустите:
~~~powershell
.\.venv\Scripts\python.exe backend/manage.py run_telegram_bot
~~~
4. Сотрудник открывает бота и отправляет /start или /id.
5. Бот показывает личный Telegram ID. Администратор проверяет принадлежность ID сотруднику и записывает его
в /admin/accounts/user/ → «Распределение лидов» → «Telegram ID (личный чат)».
6. У клиента можно заполнить «Район» в админке.
7. Создайте новый лид и назначьте сотрудника через Kanban.

Для работы нужны запущенный процесс бота и доступ к api.telegram.org. Django runserver для polling не обязателен,
но нужен для интерфейса CRM. Остановка бота: Ctrl+C.
Публичный адрес, HTTPS-туннель и webhook для этого варианта не нужны.
Если у токена уже настроен webhook, команда остановится: используйте отдельного бота или осознанно отключите webhook.
При смене бота учитывайте сохранённый offset в TelegramBotState; текущая реализация рассчитана на один бот.

## Доставка и доступ
Ручное назначение через админку не создаёт уведомление; интегрирована операция распределения недели 7.
Очередь создаётся и без заполненного Telegram ID: отправка ждёт подключения сотрудника.
Без токена команда сразу объясняет, чего не хватает; назначение в CRM продолжает работать.
Повтор после ошибки отправки выполняется с увеличивающейся задержкой, максимум час.
Устаревшие назначения отменяются перед отправкой.
Сотрудник должен оставаться активным и иметь is_staff.
Telegram ID уникален и должен быть положительным: поддерживаются личные чаты, не группы.

Кнопки проверяют личный чат, отправителя, текущий Telegram ID сотрудника, сообщение, назначение и статус.
Идентификатор уведомления уникален: старая кнопка после повторного назначения не управляет новым назначением.
Повторное принятие не создаёт новых записей. Чужие, устаревшие и недопустимые действия не меняют лид.
Действия Telegram не требуют общего leads.change_lead: разрешены только текущему назначенному сотруднику.

Один процесс polling защищён PostgreSQL advisory lock. Offset обновлений сохраняется в базе.
Вызовы Telegram не выполняются во время распределения: сеть используется только процессом бота.
Во время отправки worker удерживает короткую транзакцию с блокировкой лида, сетевой таймаут — 25 секунд.
В редком случае Telegram принял сообщение, а процесс упал до записи результата, повторная доставка может создать дубль.
Если ответ на кнопку не отправился, статус в CRM уже мог сохраниться; ориентируйтесь на CRM и повторите действие.
Это учебная интеграция, не гарантия exactly-once доставки.

## Файлы
- accounts/models.py — Telegram ID сотрудника.
- customers/models.py — район клиента.
- leads/models.py — TelegramNotice (очередь) и TelegramBotState (offset).
- leads/assignment.py — постановка уведомления в очередь.
- leads/telegram.py — транспорт, сообщение, кнопки и проверки переходов.
- leads/management/commands/run_telegram_bot.py — polling и отправка очереди.
- leads/test_telegram.py — тесты с имитацией Telegram API.

Миграции применены. Проверено 46 тестов на SQLite.
Реальная доставка требует вашего токена и подключения сотрудников; в тестах сообщения не отправляются.
Официальная документация: [Telegram Bot API](https://core.telegram.org/bots/api).
