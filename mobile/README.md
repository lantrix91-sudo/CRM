# CRM Master — Android для мастеров

Нативный клиент React Native / Expo SDK 57. Сервер — существующий Django CRM.
Операторы и руководители продолжают использовать сайт.

## Что работает

- Вход по существующему логину и паролю мастера.
- Свои активные заказы и постраничная история.
- Принятие и отказ от ещё не принятого заказа.
- Контакты клиента после принятия; звонок и WhatsApp.
- Завершение: сумма, расходы, комментарий, серверный предпросмотр и подтверждение.
- Сумма 0 означает бесплатное завершение. Повторный ремонт — только бесплатно.
- Получение оплаты по старому заказу, который действительно ожидает оплату.
- Расчёты за сегодня, месяц, текущую смену и долг компании.
- Обновление при возвращении в приложение и жестом вниз.
- Сессия хранится в Android SecureStore, истекает через 7 дней и отзывается при выходе/смене пароля.

Push-уведомления Android, автономная работа, фото и публикация в Google Play в эту версию не входят.
Уведомления о назначениях продолжает отправлять существующий Telegram-worker.
Приложение требует подключения к серверу. Финансовые действия не ставятся в офлайн-очередь.
После сетевого тайм-аута обновите заказ перед повтором действия.

## Подготовить сервер после деплоя

1. Установить зависимости корневого requirements.txt.
2. Применить миграции: python backend/manage.py migrate.
3. Добавить домен в DJANGO_ALLOWED_HOSTS, например crm.example.kz.
4. Настроить HTTPS на reverse proxy и обычные production-настройки Django.
5. Мобильные маршруты доступны под /api/mobile/. Не перенаправлять их на HTML-страницу входа.
6. Создать/проверить активную учётную запись с ролью worker.
7. Для нескольких серверных процессов настроить общий Django cache для ограничения попыток входа.

Адрес сервера вводится при входе, например https://crm.example.kz.
Разрешён только HTTPS без пути, параметров и встроенного логина/пароля.
Не используйте 127.0.0.1: на телефоне это сам телефон.
Доступ к чужим заказам проверяется сервером при каждом чтении и изменении.

## Разработка

Из папки mobile:

    npm ci
    npm start

Открыть проект в совместимой Expo Go либо Android development build.
Ввести адрес доступного HTTPS-сервера и логин мастера.

Проверки:

    npm run typecheck
    npm run export:android

export:android проверяет упаковку JS и ресурсов. Это НЕ готовый APK.

## APK для установки на телефон

В папке mobile, после входа в собственный Expo-аккаунт:

    npx eas-cli login
    npx eas-cli build:configure
    npx eas-cli build --platform android --profile preview

Профиль preview в eas.json создаёт APK; production — AAB для Google Play.
EAS загружает мобильный проект на сервер сборки Expo. Пароли CRM в проект не записывайте.
Конфигурация проекта/подпись Android создаются при первой сборке.
Идентификатор приложения: kz.crm.master. Перед публикацией его можно заменить на свой.

Без Expo-аккаунта можно собрать локально через Android Studio:
установить JDK и Android SDK, выполнить npx expo prebuild --platform android,
затем открыть mobile/android и настроить подпись release-сборки.

На текущем компьютере не обнаружены java/adb в PATH; APK здесь не собран.
Проверка на реальном Android-устройстве и подключение к production HTTPS остаются обязательными перед распространением.

Документация:
- https://docs.expo.dev/versions/v57.0.0/
- https://docs.expo.dev/build-reference/apk/
- https://docs.expo.dev/versions/latest/sdk/securestore/

## Локальная разработка по Wi-Fi

В Expo Go / debug-сборке разрешён HTTP только для частных IPv4-адресов и loopback.
В release/preview APK по-прежнему требуется HTTPS.

1. На компьютере: python backend/manage.py runserver 0.0.0.0:8000.
2. В .env: DJANGO_ALLOWED_HOSTS=127.0.0.1,localhost,192.168.3.104.
3. В mobile: npm start -- --clear; открыть проект через Expo Go.
4. В приложении ввести http://192.168.3.104:8000 (без https).
Телефон и компьютер должны быть в одной сети. Если IP изменится, обновите адрес.
